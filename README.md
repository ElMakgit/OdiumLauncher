# Odium Launcher (PortableMC)

Портативный лаунчер Minecraft Java для Windows и macOS. По умолчанию данные
хранятся в `%LOCALAPPDATA%\OdiumLauncher` (на macOS — в
`~/Library/Application Support/OdiumLauncher`), а `portable.flag` рядом с `.exe`
(или запуск с съёмного диска) переносит их в папку `launcher_data` рядом с
лаунчером — без установки, реестра и прав администратора. Лаунчер сам находит
или скачивает подходящую Java (8/17/21 в зависимости от версии Minecraft), ставит
Fabric/Quilt или Forge/NeoForge, синхронизирует модпак, добавляет сервер в
список и запускает игру.

## Возможности

- Портативные пути: всё рассчитывается от расположения `.exe`, а не от текущей
  директории.
- Источники сборок: JSON-манифест, Modrinth `.mrpack`, встроенный vanilla,
  локальный `file://`, GitHub-репозиторий.
- GitHub-автообновление: достаточно указать `https://github.com/owner/repo`.
  Лаунчер выбирает самый новый `.mrpack` в корне репозитория или в последнем
  релизе (natural-sort: `2.10` новее `2.9`, `2.3.1` новее `2.3`), проверяет
  обновление перед каждым запуском и ставит его игроку. Ответ API кэшируется
  с `ETag`, поэтому неизменённая сборка не тратит лимит GitHub.
- Загрузки: потоковая запись в `.part`, ограничение параллелизма, SHA-1/256/512,
  докачка через `Range`, кэш хэшей по size+mtime.
- Безопасная распаковка ZIP: защита от zip-slip и симлинков, лимиты размера.
- Загрузчики: Fabric, Quilt (profile JSON), Forge, NeoForge (headless installer).
- Сборки: дельта-синк, optional files, overrides, автоматическое удаление
  устаревших файлов.
- Сброс сборки: кнопка «Удалить файлы сборки» удаляет моды, конфиги и кэш
  манифеста, но сохраняет миры, скриншоты и логи; следующий запуск скачивает
  пак заново.
- Полное удаление: «Настройки» → «Удаление» стирает папку данных и сам
  `OdiumLauncher.exe` после двойного подтверждения.
- Пять тем: Windows 98 / 7 / 8.1 / 10 / 11; для Win7 — Aero-стекло.
- Размер шрифта: 90 / 110 / 130 / 150 % (по умолчанию 110 %).
- Публикация: GitHub Releases для `.mrpack`, Git Data API для manifest-паков,
  сборка готового `dist/` + ZIP. Окно «Издатель» — отдельное окно ОС, его можно
  перетащить на другой монитор.
- NeoForge ставится из архива, встроенного в exe: установка лоадера не зависит
  от `maven.neoforged.net` и его зеркал. Сеть нужна только для файлов Mojang.
- Диагностика: настройки → «Экспорт диагностики» (один файл для поддержки).
- «Настройки» тоже открываются отдельным перемещаемым окном.
- Отмена: загрузки и сетевые этапы останавливаются за секунды; уже запущенная
  игра отменой не затрагивается.
- UI не ждёт диск: `config.json` пишется фоновым потоком с объединением
  всплесков, чтение выбранной сборки и экспорт диагностики идут через
  `spawn_blocking`, системные шрифты читаются один раз и переиспользуются при
  смене темы.
- Релизы сопровождаются файлами `.sha256` для exe и DMG.

## Сборка

Требования: Rust 1.82+, Windows 10/11 (для UI), Git.

```powershell
./tools/fetch-offline-bundles.ps1   # архивы NeoForge (~43 МБ) для встраивания
cargo build --release
# target/release/OdiumLauncher.exe, около 50 МБ
```

Без `dist/neoforge-mirror/` сборка тоже проходит: exe получится примерно на
43 МБ меньше, а лоадер при первой установке будет скачан с зеркал. Релизные
сборки CI всегда скачивают архивы и собираются с `ODIUM_BUNDLES=require`, так
что опубликованный exe офлайн-режим не теряет.

### macOS

Сборка выполняется на macOS (Intel или Apple Silicon) с установленными
Rust и Xcode Command Line Tools. Скрипт собирает универсальный бинарник,
упаковывает `.app`, подписывает его ad-hoc и создаёт DMG:

```bash
# архивы NeoForge для встраивания (PowerShell-скрипт выше — только Windows)
base=https://github.com/ElMakgit/OdiumLauncher/releases/download/neoforge-mirror
mkdir -p dist/neoforge-mirror
for f in neoforge-21.1.248-offline.zip neoforge-1.20.1-47.1.79-offline.zip; do
  curl -fL -o "dist/neoforge-mirror/$f" "$base/$f"
done
./tools/package-macos.sh
# dist/OdiumLauncher-macos-universal.dmg
```

Без сертификата Apple Developer приложение не нотаризовано: при первом
запуске на другом Mac его нужно открыть через правый клик → «Открыть»
(либо снять карантин: `xattr -dr com.apple.quarantine "/Applications/Odium Launcher.app"`).
Данные на macOS хранятся в `~/Library/Application Support/OdiumLauncher`.

Тег `v*` запускает GitHub Actions, который собирает Windows `.exe` и
macOS `.dmg`, считает для обоих SHA-256 и прикладывает к релизу сами файлы и
их `.sha256`.

Проверки, которые выполняет CI:

```powershell
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
powershell -ExecutionPolicy Bypass -File tools/Check-RepoHygiene.ps1
```

## Запуск и хранение данных

По умолчанию лаунчер пишет изменяемые файлы в
`%LOCALAPPDATA%\OdiumLauncher` (на других ОС — XDG data dir). Это позволяет
держать `.exe` на рабочем столе и не засорять папку Downloads.

Портативный режим включается одним из способов:

- положить пустой файл `portable.flag` рядом с `OdiumLauncher.exe`;
- задать переменную окружения `ODIUM_PORTABLE=1`;
- запустить лаунчер с USB-накопителя или SD-карты (определяется автоматически).

В этом режиме рядом с `.exe` создаётся:

```text
OdiumLauncher.exe
portable.flag
launcher_data/
  config.json                 настройки игрока и источники
  logs/                       launcher.log-* и game-*.log (хранятся 14 дней)
  meta/                       кэш манифестов, резолва GitHub и .mrpack
  java/                       скачанные JRE (Temurin 8/17/21)
  libraries/                  библиотеки Minecraft и загрузчиков
  assets/                     ресурсы и natives
  versions/                   version JSON и client.jar
  instances/<source_id>/      файлы конкретной сборки
```

Перенос на другой компьютер — скопировать `.exe`, `portable.flag` и
`launcher_data` целиком. Папка `dist/`, которую собирает «Издатель», уже
содержит `portable.flag`, поэтому у игрока данные останутся внутри сборки.
`config.json` пишется атомарно; повреждённый файл сохраняется как
`config.json.broken.<timestamp>`.

### Пример `config.json`

```json
{
  "schema_version": 1,
  "nick": "Player",
  "sources": [
    {
      "id": "my-pack",
      "name": "My Pack 1.0.0",
      "manifest_url": "https://raw.githubusercontent.com/owner/repo/main/manifest.json"
    }
  ],
  "active_source_id": "my-pack",
  "jvm": { "xms": 1024, "xmx": 6144, "auto_xmx": true },
  "server": { "ip": "127.0.0.1", "port": 25565 },
  "optional_mods_overrides": {
    "my-pack": { "mods/shaders.jar": false }
  },
  "close_launcher_on_start": true,
  "download_concurrency": 8,
  "welcome_seen": true,
  "theme": "win98"
}
```

`kind` у источника можно не указывать: `.mrpack` определяется по расширению,
`https://github.com/owner/repo` — как GitHub-источник, остальное считается
JSON-манифестом. Допустимые схемы URL: `https://`, `http://`, `file://`,
`builtin://`.

Источник с автообновлением из GitHub выглядит так:

```json
{
  "id": "odium",
  "name": "Odium",
  "manifest_url": "https://github.com/ElMakgit/Odium",
  "kind": "github"
}
```

Старые конфиги с точной ссылкой на `.mrpack` (`raw.githubusercontent.com/...`
или `github.com/.../releases/download/...`) при загрузке автоматически
переписываются на страницу репозитория, поэтому игроку не нужно менять
`config.json` после обновления сборки. Прямая ссылка на архив остаётся
поддерживаемой, если нужна жёсткая фиксация версии.

## Удаление лаунчера

«Настройки» → «Удаление» → «Удалить лаунчер…» стирает всё, что создал лаунчер:

- папку данных целиком (`%LOCALAPPDATA%\OdiumLauncher`, в портативном режиме —
  `launcher_data` рядом с `.exe`): настройки, логи, кэш, Java, библиотеки,
  версии, сборки, миры и скриншоты;
- сам файл `OdiumLauncher.exe` — отдельным процессом уже после выхода лаунчера,
  потому что Windows не даёт удалить запущенный образ.

Перед удалением окно показывает точный путь и список того, что исчезнет, а
кнопка «Удалить всё и выйти» включается только после отметки «Я понимаю, что
данные не восстановить». Отменить удаление нельзя. Пока игра запущена, кнопка
недоступна: занятые файлы удалить не получится. Если что-то всё же осталось
(например, файл держит антивирус), лаунчер покажет список оставшихся файлов и
не закроется, чтобы можно было повторить попытку.

Лаунчер не пишет в реестр, поэтому после этой операции на диске не остаётся
ничего, что создал лаунчер.

## Жизненный цикл игры

- Пайплайн: манифест → Java → загрузчик → синхронизация → Minecraft → JVM.
- После `GameStarted` лаунчер больше не держит процесс в пайплайне: отдельная
  задача ждёт завершения и присылает `GameExited`.
- Если включено «Закрывать лаунчер после запуска», окно закрывается сразу после
  старта JVM. Игра продолжает работать: stdout/stderr пишутся в
  `launcher_data/logs/game-*.log`, а не в pipe.
- Пока лаунчер открыт, журнал игры обновляется каждые 500 мс. Повторный запуск
  заблокирован, пока игра не завершится (или пока окно не закрыто).
- «Отмена» работает на этапах загрузки/подготовки. Уже начатый процесс Java
  отменой не убивается — это осознанное поведение.

## Безопасность

- Все файлы с манифестом проверяются по хэшу; `.part` не считается готовым
  файлом.
- ZIP/mrpack распаковываются с проверкой относительных путей, защитой от
  symlink и лимитами на число записей и суммарный объём.
- Артефакты Minecraft (client jar, libraries, natives, asset index) принимаются
  только по HTTPS с хостов Mojang, Fabric, Quilt, Forge и NeoForge. Сторонний
  loader-профиль не может подсунуть `file://` или свой хост в classpath.
- Источник по `http://` помечается в UI предупреждением: издателю стоит включить
  HTTPS.
- GitHub-токен вводится в память UI и не сохраняется на диск. В legacy-скрипте
  `tools/Publish-Pack.ps1` токен передаётся git через credential helper из
  переменной окружения, а не через URL/аргументы процесса.
- `tools/Check-RepoHygiene.ps1` в CI запрещает коммитить `target/`,
  `launcher_data/`, `dist/`, готовые ZIP/EXE и похожие на секреты строки.

## Брендирование

Домен не нужно править под новый дистрибутив: значения задаются переменными
окружения на этапе сборки.

```powershell
$env:ODIUM_BRAND_NAME          = "My Launcher"
$env:ODIUM_SERVER_LIST_NAME    = "My Server"
$env:ODIUM_DEFAULT_SOURCE_ID   = "my-pack"
$env:ODIUM_DEFAULT_SOURCE_NAME = "My Pack"
$env:ODIUM_DEFAULT_SOURCE_URL  = "https://example.com/manifest.json"
$env:ODIUM_DEFAULT_SERVER_IP   = "127.0.0.1"
$env:ODIUM_DEFAULT_SERVER_PORT = "25565"
cargo build --release
```

Без переменных остаются текущие значения Odium. Готовый `dist/` всегда
содержит собственный `config.json`, поэтому конкретная сборка игрока не зависит
от этих дефолтов.

## Если не скачивается NeoForge

Ошибка вида «`.sha1/.sha256 для … недоступен`» означает, что установщик не
удалось получить ни с `maven.neoforged.net`, ни с публичных зеркал, ни из
резервного архива. Установка без проверки не выполняется. В скобках указывается
причина:

- **`TLS: …`** — клиент не доверяет сертификату. Обычно это старые версии
  Windows (7, 8.1, давно не обновлённая 10), в хранилище которых нет корневого
  сертификата `ISRG Root X2`. Лаунчер использует встроенные корни Mozilla,
  поэтому достаточно установить обновления Windows.
- **`таймаут соединения` / `нет соединения` / `HTTP 403`** — сеть не пускает к
  `maven.neoforged.net` (блокировка провайдера, файрвол, антивирус).

**Встроенный набор.** Релизный exe содержит архивы NeoForge
внутри себя (`neoforge-21.1.248-offline.zip` и
`neoforge-1.20.1-47.1.79-offline.zip`, около 43 МБ). Установка лоадера в этом
случае вообще не обращается к `maven.neoforged.net`, зеркалам и GitHub: архив
проверяется по SHA-256, раскладывается в `loaders/`, а установщик получает из
сети только файлы Mojang (`libraries.minecraft.net`, `piston-data.mojang.com`).
Поэтому блокировка NeoForge-хостов на установку больше не влияет. Цепочка ниже
работает как резерв — для dev-сборок без встроенных архивов и для будущих
версий лоадера, которых ещё нет в exe.

**Цепочка загрузки.** Лаунчер пробует по порядку: официальный
`maven.neoforged.net` → `neoforged.forgecdn.net` → `maven.creeperhost.net`
(зеркало, которое рекомендует сам NeoForged) → `mirrors.neoforged.net` →
архив в GitHub Releases проекта (тег `neoforge-mirror`, в том числе через
публичные прокси GitHub). Установщик и библиотеки проверяются по SHA-1 из
`install_profile.json`, архив — по SHA-256. Библиотеки Mojang при этом
по-прежнему скачиваются с `libraries.minecraft.net`, поэтому резервный набор
содержит только артефакты NeoForge.

**Докачка при обрыве.** Файл скачивается в `.part` и переключается на следующее
зеркало без потери уже полученных байт: если зеркало закрылось на середине
архива, докачивается только хвост, а не весь файл. Если сервер вернул не тот
диапазон или другую версию файла, префикс отбрасывается и загрузка начинается
заново с проверкой контрольной суммы. Хост, который дважды подвёл, на время
уходит в конец очереди (circuit breaker), но не исключается совсем.

Если установка всё равно не проходит, пришлите строку из скобок и файл лога из
`%LOCALAPPDATA%\OdiumLauncher\logs`: по ним видно, отказал ли TLS, сеть или
резервный набор.

## Резервный набор NeoForge (для сопровождающих)

Набор собирается скриптом и публикуется в релизе с тегом `neoforge-mirror`:

```powershell
python tools/build-neoforge-bundle.py --minecraft 1.21.1 --loader 21.1.248
gh release upload neoforge-mirror neoforge-21.1.248-offline.zip --clobber
```

Скрипт скачивает установщик и все артефакты, которые тот берёт с
`maven.neoforged.net`, проверяет их SHA-1 и печатает SHA-256 архива. Полученный
хеш и размер нужно вписать в `OFFLINE_BUNDLES` в
`crates/pml-loader/src/lib.rs` — без этого лаунчер не станет использовать новый
набор. Библиотеки Mojang в архив не входят намеренно.

Перед релизной сборкой архивы кладутся в `dist/neoforge-mirror/` (папка не
входит в git):

```powershell
tools/fetch-offline-bundles.ps1        # скачивает и сверяет SHA-256
$env:ODIUM_BUNDLES = "require"         # без архивов сборка упадёт
cargo build --release
```

`crates/pml-loader/build.rs` вшивает найденные архивы в бинарник; при
`ODIUM_BUNDLES=require` отсутствие любого из них — ошибка сборки, поэтому
релиз не может незаметно остаться без офлайн-режима. Обычная dev-сборка без
`dist/` тоже валидна: лаунчер просто скачает архив при первой установке.

## Память

Лаунчер держит одно окно и не открывает документов, поэтому его память — это
цена окна: шрифты, тесселяция кадра и commit драйвера видеокарты. Замеры
делает `tools/Measure-Memory.ps1` на релизной сборке; методика, сценарии и
таблица вариантов — в [docs/memory.md](docs/memory.md).

```powershell
cargo build --release
./tools/Measure-Memory.ps1 -Scenarios -IdleSeconds 30 -PeakSeconds 15
```

Бюджет 0.1.7 (Windows 11, Ryzen 5 3600, RTX 5070, экран 3440×1440):

| Сценарий | private bytes, median | working set, median |
|---|---:|---:|
| Простой 20 с | 144,5 МБ | 91,5 МБ |
| Окно на весь экран | 176,7 МБ | 91,5 МБ |
| Возврат к окну | 145,9 МБ | 91,5 МБ |
| После 20 циклов свернуть/развернуть | 145,8 МБ | 91,5 МБ |

Цель — до 150 МБ private bytes в простое и до 200 МБ на весь экран; возврат
после разворачивания должен укладываться в простой + 20%. Заметное отклонение
от этих цифр считается регрессией: сначала разбираемся, потом выпускаем.

## Ограничения

- Оконные эффекты (Aero-стекло в теме Windows 7) есть только на Windows. На
  macOS лаунчер собирается и работает, но без стекла.
- Offline-режим использует offline UUID (`MD5` v3); аккаунты Microsoft не
  поддерживаются.
- Forge/NeoForge ставятся внешним installer'ом: диагностика ограничена его
  выводом и таймаутом.
- Публикация через `pml-publish` требует токен с `repo` / `Contents: write`.
